Scripted units, not a model: this report is the plumbing test of the probe arm (#200), and it says nothing about whether the advice edit helps. A probe reruns one arm of a committed report beside the same arm with one advice file replaced, under the suite file the committed report ran under. Here the committed report is drift-scripted-reference.json, the rerun arm is treatment, and the probe arm is treatment with regulator/advice/implement.md seeded from evals/advice/inherited-suite/implement.md, which is the definition's seed for the implement profile plus one line asking the unit to run the inherited suite before it reports. The fingerprint names evals/drift.json at the hash the reference report names; the probe record names the reference report's hash, the override's hash and the cost of the run, which is 0 because a scripted unit runs no session and so no ledger was written. n is three repetitions of six units per arm, 18 runs, and the six units of a repetition are not independent; a scripted unit is deterministic, so every interval is a point. The two arms are the same run: on every repetition and task the probe arm's outcome and every pre-registered count equal the treatment's, wall-clock aside, and evals.test.ts checks this row by row. That is by construction, because the scripted reference unit reads no advice; the instances differ in the one seeded file and nothing else, which evals.test.ts also checks by comparing the fixture commits. Where the gated arm lost: nowhere, and that is the point of this report. An advice edit can only change what a model does with its context, and no model ran. No prediction is bound to this report, so it resolves no probe horizon. The first live probe is a spend decision for whoever plans it, and it needs a live baseline written under the current suite (version 2), because the first live report predates the fingerprint's suite hash and cannot be a probe's baseline.
