How it works · drawn from the reference build at checkpoint 9

One unit, end to end.

The orchestrator never touches the code. It writes a contract, hands a session a worktree, reads the report the session wrote, re-runs the checks itself against the commit, and merges or routes. Everything on this page is what course/lab/src/controller.ts and checkpoints 2–9 actually do; nothing is aspirational.

The loop

Orchestrator, session, worktree, stores

Five participants. The orchestrator is the S3 loop in the base checkout. The session is Pi with the checkpoints loaded, running in a git worktree that belongs to exactly one unit. The domain — the repository — is on the far right and is only ever read as a domain: never as state.

  1. ContractThe orchestrator checks the contract (shape, consistency, a unit type the workload declares) and records the unit under it. The contract file is immutable; a new version is a replan, not a retry.
  2. DispatchA lease and a worktree are taken for the unit — a branch unit/u1 checked out under .regulator/worktrees/u1 — and a Pi session starts there with the definition's checkpoints, and nothing the project supplies, loaded.
  3. SessionThe gates find the unit the way S3 recorded it: the lease whose resource is this worktree, then the contract from the store. The contract becomes a system-prompt section (advice) and a typed session entry (state).
  4. SessionThe model works inside the gates. Writes need the profile's grant and a live lease and must not touch identity or protected paths; the budget meter counts every turn; tool errors become observations; run_tests results are stamped with the revision they ran at.
  5. SessionIt commits and calls report_result — the only way a unit ends well. The report is refused unless it honours the contract and cites runs that happened here, on the committed tree, and passed.
  6. VerifyThe orchestrator reads the report, never the diff, and re-runs the workload's checks itself against the commit. Evidence and the verdict go to the audit log; a claim in the report that the host contradicts is named.
  7. CloseOn pass, the branch is merged into the base, the worktree removed, the lease released. On anything else the attempt is recorded as it ended and the unit is blocked.
  8. RouteA blocked unit is routed under the versioned recovery policy: the cause is classified from the orchestrator's records first, then S2's signals, then the session's observations; the Nth occurrence takes the Nth action; retry and repair spend attempts and become escalate at the ceiling.
A work contract

What a unit is authorized to decide

This is the real first contract from the lab, course/lab/contracts/fix-known-issue.json, unchanged. A contract is not a task description: it allocates decisions. Some are fixed before the unit runs, some are delegated within bounds, and some are explicitly nobody's yet — and the report is refused if it settles one of those.

{
  "kind": "task",
  "id": "tc-fix-known-issue",
  "version": 1,
  "unitId": "u1",
  "unitType": "implement",
  "workload": { "name": "software-development", "version": 1 },
  "objective": "Fix the known issue described in the README so that
                the project's own test suite passes.",
  "contribution": "First contracted unit against the fixture: proves
                   the loop before the loop is trusted with anything larger.",
  "constraintRefs": ["reg.authority.vendor-write-gate.v1"],
  "fixed": [
    { "id": "f-signature", "subject": "public signature of slugify",
      "decision": "slugify remains a single-argument function returning
                   a string; no options object, no second parameter.",
      "authorityRef": "S3 planning decision P1 (lesson 06)" },
    { "id": "f-vendor", "subject": "vendored helper",
      "decision": "vendor/left-pad.js is not modified, wrapped, or replaced.",
      "authorityRef": "reg.authority.vendor-write-gate.v1" }
  ],
  "delegated": [
    { "id": "d-helpers", "subject": "private helper decomposition",
      "bounds": "Private helpers inside src/slugify.js only;
                 no new modules, no new dependencies." },
    { "id": "d-tests", "subject": "additional test cases",
      "bounds": "May add cases to the existing test files under test/;
                 may not delete or weaken an existing assertion." }
  ],
  "unresolved": [
    { "id": "u-unicode", "subject": "non-ASCII input",
      "reason": "Nobody has decided whether accented characters are
                 transliterated, stripped, or preserved.",
      "handling": "defer" }
  ],
  "expectedEvidence": [
    { "id": "e-tests",  "description": "run_tests reports every test passing",
      "class": "test",    "required": true },
    { "id": "e-checks", "description": "run_checks reports every check passing",
      "class": "command", "required": true }
  ],
  "provenance": { "createdBy": "S3", "createdAt": "2026-09-22T00:00:00.000Z" }
}
version · unitTypeThe store keeps contract.v1.json immutably. The unit type selects the capability profile the session runs under and the checks the orchestrator re-runs at closeout, both from the workload definition — the contract does not name a model or a tool.
fixedDecisions already made, with the authority that made them. The report may not silently deviate: a deviation from a fixed decision must be declared and becomes a blocking signal for S3. f-vendor is also a gate; the contract restates it so the unit knows why the gate refuses.
delegatedDecisions the unit makes, within bounds. The report must say what it chose for each one; a missing choice is refused at the tool and again at close.
unresolvedDecisions nobody has made. The unit may preserve them (leave the behaviour untouched) or surface them (report what it found); there is no settled. A report that omits u-unicode is refused: "settled silently or forgotten".
expectedEvidenceThe criteria the closeout gate binds host-run evidence to, by class. The unit's own run_tests call satisfies the report's shape; only the orchestrator's re-run at the committed revision satisfies the criterion.
The result report

What the unit says back, and who checks which field

The report is the only thing the orchestrator reads about the work. It is written by a typed tool the session calls once, checked against the exact contract version at the tool and again at close, and then contradicted or not by evidence the orchestrator produced itself.

{
  "contractId": "tc-fix-known-issue", "contractVersion": 1,
  "unitId": "u1", "attempt": 1, "reportedAt": "…",
  "summary": "Collapsed repeated separators and trimmed dashes; all tests pass.",
  "evidence": [
    { "class": "test",    "ref": "run_tests",  "observation": "4 passed, 0 failed" },
    { "class": "command", "ref": "run_checks", "observation": "2 ok" }
  ],
  "delegatedResults": [
    { "decisionId": "d-helpers", "choice": "one private collapse() helper" },
    { "decisionId": "d-tests",   "choice": "added two edge cases" }
  ],
  "unresolvedOutcomes": [
    { "decisionId": "u-unicode", "outcome": "preserved",
      "note": "accented input still passes through untouched" }
  ],
  "emergentDecisions": [
    { "subject": "trailing whitespace", "choiceOrQuestion": "trimmed it",
      "consequenceIfWrong": "low" }
  ],
  "deviations": [],
  "residualUncertainty": []
}
attemptOne report per contract version and attempt: a repair attempt writes its own. Never revised.
evidenceChecked for shape at the tool (every required class present) and for provenance before the tool runs (the run happened in this session, at HEAD, on a clean tree, and passed). Then the closeout gate re-runs the checks and, if they fail, lists this claim as contradicted.
delegatedResults · unresolvedOutcomesChecked at the tool and at close: every delegated decision has a choice; every unresolved decision has an outcome of preserved or surfaced.
emergentDecisions · deviationsNot gated — recorded. A high-consequence emergent decision and every deviation become typed signals for S3 at close.

Three stores

Nothing reads its own progress off the domain

INV-005. Execution state, regulatory state and the domain are three different things with three different owners, and no arrow below is inferred from another. The orchestrator knows what it dispatched because it wrote it down, not because it looked at the diff.

Recovery

What happens on attempt two, and on attempt six

A blocked unit is not retried; it is routed. The cause is a closed set, classified in a fixed order; the action comes from a versioned policy, by occurrence; the attempt ceiling is the floor under the lattice.

Inside a session

Which checkpoint answers which event

A unit's session is plain Pi with eight extensions loaded in order. Each hooks a few lifecycle events; a rule is a sentence here because a table says it faster than a picture would.

project_trustcp9 · authorityAnswers no: the project never loads its own extensions or skills. (The dispatcher's loader enforces the same rule for SDK sessions, where this event never fires.)
session_startcp4 · cp5 · cp6 · cp7 · cp8 · cp9Find the unit from the lease on this worktree; load the contract from the store and append it as a typed entry; open the budget ledger; reconcile pending effects against the world; discover the protected paths; load the canaries.
before_agent_startcp3 · cp5Add the profile's advice and the contract as system-prompt sections. Advice — the gates below are what bind.
tool_callcp1 · cp3 · cp4 · cp6 · cp8 · cp9In load order: vendor path (lexical), profile grant, live lease for any non-read-only effect, budget crossed → refuse effects, report_result preflight (the cited runs happened here, at HEAD, and passed), protected-path preflight with the filesystem walk; the path a tool executes is the one that was checked. On disk

An instance, after one routed unit

Everything the orchestrator and the regulators know lives under .regulator/ in the base checkout, ignored by git. The repository itself is the domain. This is what a fixture looks like after a unit was blocked at verification, repaired, and closed.

<repo>/
  src/ test/ vendor/            the domain
  regulator/identity/           INVARIANTS.md — write-protected
  .regulator/                   the instance (ignored by git)
    units/u1/
      unit.json                 closed · attempts 2
      contract.v1.json          immutable
      report.v1.a1.json         attempt 1's report (refused at close)
      report.v1.a2.json         attempt 2's report
      attempts.ndjson           check-failure · reported
      budget.a1.json            the ledger of attempt 1
      budget.a2.json
      observations.ndjson       what the session saw fail
      decisions.ndjson          check-failure → repair (recovery v1)
    leases/                     empty: released at close
    worktrees/                  empty: removed at close
    audit.ndjson                evidence ×5, verdicts ×2 (fail, pass)
    signals.ndjson              audit-finding S3*→S3 (closeout refused),
                                its obligation: opened → resolved (rework)
    effects.ndjson              notify_owner: intended, committed
    trace.ndjson                one record per turn (cp1)
    canaries                    values that must never leak
Two immutable files per attempt, one mutableThe contract and each report are written once with wx and never overwritten; unit.json is the one thing that changes, and it holds only status and the attempt count.
Append-only logs, replayableAttempts, observations, decisions, audit entries, signals and effects are NDJSON lines validated on write and on read. regulator unit evidence u1 and the control room's inspector are replays of these files.
The read modelregulator status --definition course/lab --instance <repo> projects the definition (registry, workload, policies) and the instance (units with contract, report, budget, decisions, verdict and what is owed on them; leases; obligations; unrouted signals) — from files only. The control room serves the same view.
What is not hereThe transcript: Pi's session file is authoritative for the conversation and the orchestrator never reads it. And any notion of progress derived from the diff.
