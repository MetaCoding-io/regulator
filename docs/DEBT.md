# Build debt

This file lists what the build knows it has not yet absorbed. Each row is one gap that
counts as *debt*: it was taken on deliberately, and there is a place where it will be
paid. A permanent limit of a mechanism is a different thing and gets no row here. The
registry cards under `packages/regulator/registry/regulators/` remain the source of truth
for what each regulator does not catch. This file indexes the subset of those limitations
that is owed, so that nothing is stated twice and nothing is stated only in a card's
fourth bullet.

Rules:

- When a new registry limitation names a later lesson, a milestone or a "not yet", it
  gets a row here in the same change. AGENTS.md states this under "Before finishing an
  issue".
- The change that pays a row also closes it. That change strikes the row, cites the
  commit or PR, and updates the card's limitation to say what the mechanism now does.
- "Resolves in" names the issue and milestone that [`ROADMAP.md`](../ROADMAP.md) assigns.
  It is not a promise of a date. A row with no issue says *unscheduled*, and when the
  reason is the deployment's, the roadmap's "Not planned" table says why.

Some limits are permanent, and they are listed here so that nobody re-files them as
debt. Prompt sections are advice and can be ignored (`contract-advice`). A model summary
can be wrong, and only the deterministic block is guaranteed
(`contract-preserving-compaction`). The evidence preflight trusts the session's own tool
run by design, and independence belongs to the closeout gate (`evidence-preflight`). An
effect with no observable trace can only be reconciled as absent (`effect-journal`). The
gate reads the report and never the diff (`result-report-gate`).
